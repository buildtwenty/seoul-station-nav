# 실내 길찾기 3D 모형 공통 틀

지하철역(seoul-station-nav)에서 쓴 구조를 대학 건물 등 다른 실내 공간에도 그대로 쓰기 위한 설명서.
다른 대화에서 "이 틀대로 ○○대학교 ○○관을 만들어 줘"라고 할 때 이 파일을 붙이면 된다.

- 작성일: 2026-10-28
- 원본 사례: 역 안 길찾기 모형(건대입구·면목), Three.js HTML 한 장

---

## 1. 핵심 원칙 네 가지

1. **데이터와 코드를 분리한다.** 공간 하나 = JSON 파일 하나. 뷰어 코드는 어떤 공간이든 같은 코드를 쓴다. 공간을 추가할 때 코드는 안 건드린다.
2. **좌표는 손으로 타이핑하지 않는다.** 도면 이미지를 띄우고 클릭해서 찍는 편집기 페이지로 만든다. 편집기 출력이 곧 JSON이다.
3. **확인한 것과 추정한 것을 데이터 안에 표시한다.** 지점·연결마다 `est` 플래그와 출처를 둔다. 화면에는 "위치 어림" 태그로 드러낸다.
4. **공식 자료가 있으면 그게 정답, 모형은 설명 장치.** 지하철은 공식 빠른환승 칸 번호가 있어서 그걸 정답으로 쓰고 모형은 "왜 그 칸인지"를 보여준다. 건물은 공식 정답이 없으니 모형 계산값이 곧 안내가 된다. 대신 현장 확인 항목을 남긴다.

## 3. 데이터 스키마 (venue JSON)

공통 뼈대. 지하철이든 건물이든 같다. 종류별 확장은 `kind`로 구분.

```jsonc
{
  "id": "kmu-engineering-hall",
  "kind": "building",               // "station" | "building"
  "name": "국민대 공학관",
  "source": {                       // 출처 기록. 추정 근거를 남긴다
    "plans": ["data/plans/kmu-eng/1F.jpg", "data/plans/kmu-eng/2F.jpg"],
    "urls": ["https://..."],
    "checked": "2026-10-28",
    "note": "캠퍼스맵 PDF 1~5층 평면도. 축척은 복도 폭 2.4 m 기준으로 보정"
  },
  "units": "m",
  "axes": { "x": "동(+)/서(-)", "y": "높이", "z": "남(+)/북(-)" },
  "yScale": 2.4,                    // 층 구분이 보이도록 높이만 과장. 뷰어에서 토글

  "floors": [                       // 층판. 한 층에 여러 조각 가능
    { "id": "1F", "label": "1층", "y": 0,   "poly": [[0,0],[60,0],[60,18],[0,18]] },
    { "id": "2F", "label": "2층", "y": 4.2, "poly": [[0,0],[60,0],[60,18],[0,18]] }
  ],

  "nodes": {                        // 지점. id → 정의
    "e_main": { "p": [30,0,18], "label": "정문", "type": "entrance", "no": 1 },
    "c1_a":   { "p": [10,0,9],  "label": "1층 복도 서쪽", "type": "corridor" },
    "s1_w":   { "p": [4,0,9],   "label": "서쪽 계단 1층", "type": "stair_landing" },
    "s2_w":   { "p": [4,4.2,9], "label": "서쪽 계단 2층", "type": "stair_landing" },
    "ev1":    { "p": [30,0,6],  "label": "엘리베이터 1층", "type": "elevator" },
    "ev2":    { "p": [30,4.2,6],"label": "엘리베이터 2층", "type": "elevator" },
    "r201":   { "p": [12,4.2,3],"label": "201호 강의실", "type": "room", "no": "201", "est": true }
  },

  "edges": [                        // 연결. [from, to, type, est(0/1)]
    ["e_main","c1_a","walk",0],
    ["c1_a","s1_w","walk",0],
    ["s1_w","s2_w","stair",0],
    ["ev1","ev2","elevator",0],
    ["s2_w","r201","walk",1]
  ],

  "goals": {                        // 목적지 묶음. UI 선택 상자에 뜨는 것
    "entrances": ["e_main"],
    "rooms": ["r201"]
  },

  "facts": {                        // 사람이 읽는 확인/추정 목록
    "ok":  ["1~5층, 계단 2개(동·서), 엘리베이터 1대 (캠퍼스맵 평면도)"],
    "est": ["201호 문 위치는 평면도 방 번호만 보고 추정"]
  }
}
```

### 노드 type 목록
| type | 뜻 | 지하철 | 건물 |
|---|---|---|---|
| `entrance` | 외부 출입구 | 출구 N번 | 정문·후문·측문 |
| `corridor` | 복도·통로 중간점 | 대합실 | 복도 |
| `stair_landing` | 계단 위·아래 끝 | 계단 | 계단 |
| `elevator` | 엘리베이터 문 앞 (층마다 하나) | 엘리베이터 | 엘리베이터 |
| `gate` | 통과 비용이 있는 문 | 개찰구 | 출입통제문·보안문 |
| `room` | 목적지 방 | (없음) | 강의실·연구실·사무실 |
| `platform_access` | 승강장에서 올라가는 입구 | 승강장 계단 입구 | (없음) |

### 연결 type과 비용 가중치
| type | 가중치 | 비고 |
|---|---|---|
| `walk` | 1.0 | 평지 |
| `escalator` | 1.1 | |
| `elevator` | 1.3 + 고정 20 m | 대기 시간을 거리로 환산 |
| `mix` | 1.4 | 계단인지 에스컬레이터인지 미확인 |
| `stair` | 1.6 | 층당 높이 × 가중치 |
| `gate` | 1.0 + 고정 6 m | |

비용 = 두 지점 사이 3D 거리 × 가중치 + 고정 비용. **교통약자 모드**는 `stair`·`escalator` 연결을 제외하고 다시 계산한다.

### 지하철 전용 확장
```jsonc
"platforms": {
  "p2o": { "line": 2, "label": "외선순환", "a": [-230,15,-7], "b": [-30,15,-7],
           "cars": 10, "doorsPerCar": 4, "car1": "a", "access": ["o_a","o_b"] }
},
"official": { "p2o>7": "8-3" }     // 공식 빠른환승 칸-문. 검증에 쓴다
```
열차 문 위치 = 승강장 a→b를 `cars × doorsPerCar`로 등분. `car1`이 1번 칸이 있는 쪽.

## 4. 좌표 규칙

- 단위 m. 원점은 공간의 대표 지점(건물은 정문 앞 바닥, 역은 주 개찰구).
- x 동(+), z 남(+), y 위(+). 도면 이미지는 보통 위가 북쪽이므로 이미지 아래 = z(+).
- **축척 보정**: 도면에 치수가 없으면 아는 길이 하나(복도 폭, 강의실 폭, 승강장 길이 = 칸 수 × 20 m)를 두 점 클릭으로 지정한다. 편집기가 px→m 변환값을 `calib.json`에 저장한다.
- 층 높이: 모르면 건물 4.2 m, 지하철 6 m(지하층 간)로 두고 `est`로 표시.
- 높이 과장 `yScale`은 렌더링 때만 곱한다. 거리 계산은 실제 높이로.

---

## 5. 경로 계산

1. 출발 후보 집합을 만든다. 건물은 선택한 출입구 하나. 지하철은 "모든 문"(칸 × 문)이 각각 후보이고, 가장 싼 문을 고른다 → 그게 하차 문 번호.
2. 각 후보에서 다익스트라로 목적지 집합(방 하나, 또는 환승 승강장의 access 전부)까지 최단 비용.
3. 결과 = 경로 노드 열 + 각 구간 type + est 플래그.
4. 공식 정답(`official`)이 있으면 계산값과 비교해 "일치/불일치" 배지를 띄운다. 불일치면 모형 좌표가 틀린 것이므로 고쳐야 한다.

## 6. 렌더링

- Three.js ES 모듈 (import map, cdnjs 고정 버전). 빌드 없음.
- 층판: `floors[].poly`를 ShapeGeometry로 압출(두께 1 m). 층마다 색 톤 다르게.
- 벽·방: 건물은 `rooms`에 폴리곤을 주면 낮은 벽(0.6 m)으로 그린다. 복도는 안 그린다.
- 계단: a→b를 5~30단 박스 계단으로. 에스컬레이터: 경사판 + 난간 두 줄. 엘리베이터: 수직 기둥(반투명) + 층마다 문 표시.
- 라벨: 캔버스 스프라이트. 출입구 번호, 방 번호, 층 이름.
- 경로: CatmullRom 튜브 + 움직이는 구슬 + 출발점 펄스 링. `prefers-reduced-motion`이면 정지.
- 카메라: 궤도 카메라. **데이터 bounding box에서 자동 프레이밍**(역마다 수동값 금지). 시점 버튼: 입체 · 위에서 · 옆에서 · 경로 맞춤.
- 다크 모드: CSS 변수에서 색을 읽어 재빌드.
- 모바일: 세로 화면이면 모형 위, 패널 아래.

## 7. 편집기 (editor.html) 작업 순서

1. 도면 이미지 올리기 (층마다 한 장). 드래그로 이미지 위치·회전을 다른 층과 맞춘다.
2. 축척: 아는 길이의 두 점 클릭 → m 입력.
3. 원점 클릭.
4. 층 선택 → 높이 입력.
5. 노드 찍기: 클릭 → type·label 입력. 방은 번호만 입력하면 label 자동.
6. 연결: 노드 두 개 차례로 클릭 → type 선택. 층 사이 연결(계단·엘리베이터)은 두 층의 같은 자리 노드를 잇는다.
7. 추정 토글: 확실치 않은 노드·연결에 `est` 체크.
8. 내보내기 → `data/venues/<id>.json` + `data/plans/<id>/calib.json`.
9. `node tools/validate.js` 통과 확인 → 뷰어에서 열어 본다.

---

## 8. 검사 항목 (tools/validate.js)

- 연결에 적힌 노드 id가 모두 존재하는가
- 모든 `entrance`에서 모든 `room`(또는 승강장)에 도달 가능한가
- 층 사이 연결이 `stair`/`escalator`/`elevator`/`mix` 중 하나인가 (walk로 층을 넘으면 오류)
- 노드 y가 `floors`에 있는 층 높이 중 하나와 일치하는가
- 지하철: `official` 값과 계산값 비교 → 불일치 목록 출력
- 통계: 노드·연결 수, est 비율(완성도로 index.json에 기록)

## 9. 도면 구하기와 주의점

**대학 건물**
- 학교 홈페이지 캠퍼스맵, 시설과 공지(리모델링 도면), 학과 홈페이지 "오시는 길", 피난안내도 사진, 건축 공모 당선작 자료.
- 국토교통부 건축물대장(세움터)은 층별 면적·층수만. 평면도는 안 나온다.
- 도면이 없을 때: 카카오맵/네이버 지도 실내 지도(일부 건물), 위성사진 외곽 + 층수로 틀만 만들고 내부는 전부 `est`.

**지하철**
- 서울교통공사 사이버스테이션 역 안내도: `https://www.seoulmetro.co.kr/common/resources/cyber/fileView.jsp?fileName=station_<역코드>.jpg` (지상 포함 안내도) 또는 `in_<역코드>.jpg` (내부 안내도). 역코드는 `/kr/getLineData.do`에서.
- 공식 빠른환승 칸·문: 국토교통부 "철도역 빠른 환승 정보" CSV(공공데이터포털 15151816, 로그인 없이 다운로드, 전국 1052건).
- 출구별 빠른하차: 서울교통공사 빠른하차정보 API(공공데이터포털 15143840, 인증키 필요).

**저작권**: 안내도·도면 이미지는 저장소에 올리지 않거나(`.gitignore`), 올릴 때 출처와 이용조건을 README에 적는다. 공공누리 1유형은 출처 표시만 하면 된다. 대학 도면은 학교 시설과에 사용 가능 여부를 묻는 게 안전하다.

## 10. 지하철 → 대학 건물로 옮길 때 달라지는 점

| 항목 | 지하철역 | 대학 건물 |
|---|---|---|
| 출발 | 내린 열차(승강장·방향) | 들어온 출입구 (또는 현재 위치 방) |
| 도착 | 출구 번호, 환승 승강장 | 방 번호 |
| 핵심 결과 | 하차 칸-문 번호 | 어느 출입구·어느 계단/엘리베이터 |
| 정답 데이터 | 공식 빠른환승 CSV | 없음 → 현장 확인 목록 |
| 층 수 | 2~4층 | 3~10층, 엘리베이터가 핵심 |
| 지형 | 평지 | 경사지 캠퍼스라 1층 출입구와 3층 출입구가 둘 다 지면일 수 있음 → `entrance`에 `groundLevel` 표시 |
| 목적지 수 | 출구 3~10개 | 방 수십~수백 개 → 검색 상자 필요 |
| 방 폴리곤 | 불필요 | 있으면 좋음(벽 렌더링) |

방이 많은 건물은 방마다 노드를 찍지 말고 **복도 노드 + 방 번호 → 가장 가까운 복도 노드 매핑**으로 줄인다. 방 노드는 "복도에서 문까지 몇 m"만 들고 있으면 된다.

## 11. 시범 건물 한 채 만드는 순서

1. 도면 확보 → `data/plans/<id>/`에 층별 이미지
2. 편집기로 1층만 먼저: 출입구 전부, 계단·엘리베이터, 복도 뼈대
3. validate 통과 → 뷰어에서 1층 모양 확인
4. 나머지 층 추가 (같은 자리 계단·엘리베이터 노드를 층마다)
5. 방 번호 매핑
6. 안내 문장 읽어 보고 어색한 규칙 수정
7. `index.json`에 등록, est 비율 기록
8. 현장 가서 est 항목 확인 → ok로 승격

## 12. 다른 대화에 넘길 때 브리프 예시

> 이 파일(indoor-3d-framework.md)의 틀대로 **○○대학교 ○○관** 3D 길찾기 모형을 만들어 줘.
> 저장소는 seoul-station-nav와 같은 구조(index.html / editor.html / src / data / tools).
> 도면은 `data/plans/<id>/`에 넣어 뒀어 (또는: 학교 홈페이지 캠퍼스맵에서 찾아 줘).
> 출발은 출입구, 도착은 방 번호. 엘리베이터 경로(교통약자 모드) 포함.
> 확인/추정을 데이터에 `est`로 표시하고 validate 통과시켜 줘.
